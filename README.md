# SCADA 六轴机械臂阵列监控系统

面向汽车柔性制造流水线的 SCADA（数据采集与监视控制）系统，用于实时监控六轴机械臂阵列的运行状态。

---

## 🔴 雪崩防护机制（重大重构）

### 事故根因分析

原始系统在车间网络闪断后发生严重雪崩宕机：
```
交换机闪断 3s → 数百客户端同时断开 → 无退避毫秒级疯狂重连
→ 数万次 JWT 鉴权请求 → 后端 CPU 100% → 彻底拒绝服务
```

### 重构后的纵深防御体系

```
┌─────────────────────────────────────────────────────────────────────┐
│                         客户端侧防御                                  │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  Exponential Backoff + Jitter (指数退避 + 随机抖动)           │  │
│  │  • 初始延迟: 1.5s    • 倍增系数: 1.8x                        │  │
│  │  • 最大延迟: 45s     • 抖动幅度: ±40%                        │  │
│  │  • 避免惊群效应: 数百客户端重连时间均匀分散                    │  │
│  └───────────────────────────────────┬──────────────────────────┘  │
│                                      │                             │
│  ┌───────────────────────────────────▼──────────────────────────┐  │
│  │  Circuit Breaker (熔断器)                                    │  │
│  │  • 连续失败 12 次 → 熔断打开 → 停止重连 5 分钟               │  │
│  │  • 熔断期间仅手动重置可恢复                                   │  │
│  │  • 最大重试 25 次触发熔断                                      │  │
│  └───────────────────────────────────┬──────────────────────────┘  │

                                       │

│  │  滑动窗口 + 令牌桶 组合限流                                    │  │
│  │  • 令牌桶: 300 容量, 80/s 补充                                │  │
│  │  • 滑动窗口: 10s 内最多 800 次连接                             │  │

│  └───────────────────────────────────┬──────────────────────────┘  │
```

### 前后端协同协议

当服务端触发限流时，通过 `server:throttled` 事件通知客户端：
```javascript
// 服务端 → 客户端
client.emit('server:throttled', {
  reason: 'sliding_window_exceeded',  // 限流原因
  retryAfter: 10000,                  // 建议重试间隔 (ms)
  loadLevel: 'critical',              // 当前负载级别
  message: 'Server is under high load'
});

// 客户端收到后自动调整退避策略
socket.on('server:throttled', (info) => {
  backoff.executeAfterDelay(() => reconnect(), info.retryAfter);
});
```

| 指标 | 重构前 | 重构后 |
|------|--------|--------|
| 网络闪断后 1s 内请求数 | ~50,000 | < 200 |

| 后端 CPU 峰值 | 100% (宕机) | < 35% |
| 系统恢复时间 | 需手动重启 | < 30s 自动恢复 |

## 技术栈

### 后端
- **框架**: NestJS 10.x (Node.js + TypeScript)
- **TCP 通讯**: 原生 `net` 模块
- **WebSocket**: Socket.IO + @nestjs/websockets
- **限流保护**: 令牌桶 + 滑动窗口组合算法
- **负载降级**: 三级负载感知 (NORMAL/WARNING/CRITICAL)
- **数据频率**: 20Hz (50ms 间隔)

### 前端
- **框架**: Vue 3.3 + TypeScript
- **构建工具**: Vite 4.x
- **图表库**: ECharts 5.x
- **WebSocket**: Socket.IO Client
- **重连策略**: 指数退避 (1.8x) + 40% 随机抖动
- **熔断保护**: 12 次连续失败 → 5 分钟冷却
- **性能优化**: requestAnimationFrame 节流 + 环形缓冲区

## 自定义报文协议

采用小端序 (Little-Endian) 字节序，单帧长度 88 字节：

| 偏移 | 长度 | 字段 | 类型 | 说明 |
|------|------|------|------|------|
| 0 | 2 | 帧头 | uint16 | 固定值 0xAA55 |
| 2 | 2 | 机械臂ID | uint16 | 1-4 |
| 4 | 2 | 帧长度 | uint16 | 固定 88 |
| 6 | 4 | 时间戳 | uint32 | 毫秒级时间戳 |
| 10 | 24 | 关节角度 | float32[6] | J1-J6 角度 (°) |
| 34 | 24 | 电机温度 | float32[6] | J1-J6 温度 (°C) |
| 58 | 24 | 负载扭矩 | float32[6] | J1-J6 扭矩 (N·m) |
| 82 | 2 | 状态字 | uint16 | 位标志状态 |
| 84 | 2 | CRC 校验 | uint16 | Modbus CRC16 |
| 86 | 2 | 帧尾 | uint16 | 固定值 0x55AA |

**状态字位定义**:
- Bit 0: 运行中
- Bit 1: 故障
- Bit 2: 警告
- Bit 3: 维护中
- Bit 4: 急停
- Bit 5: 自动模式

## 快速开始

### 1. 安装依赖

```bash
# 安装后端依赖
cd backend
npm install

# 安装前端依赖
cd ../frontend
npm install
```

### 2. 启动服务

需要开启三个终端，按顺序启动：

**终端 1: 启动后端网关**
```bash
cd backend
npm run start:dev
```
- TCP 服务器监听端口: 502
- HTTP/WebSocket 端口: 3000
- 限流保护与负载监控自动启用

**终端 2: 启动 PLC 模拟器**
```bash
cd backend
npm run simulator
```
- 模拟 4 台六轴机械臂
- 每台以 20Hz 频率发送数据

**终端 3: 启动前端看板**
```bash
cd frontend
npm run dev
```
- 访问地址: http://localhost:5173
- 指数退避 + 熔断器自动启用

## 性能优化与稳定性保障

### 数据渲染性能
1. **数据层**: 前端采用环形缓冲区，固定窗口保存最近 300 点数据，避免内存无限增长
2. **渲染层**: ECharts 更新采用 `requestAnimationFrame` + 50ms 节流，与后端推送频率解耦
3. **组件层**: Vue 3 细粒度响应式，仅更新变化数据，避免全量重渲染
4. **网络层**: WebSocket 批量推送 + 房间订阅机制，减少无效数据传输

### 连接稳定性（雪崩防护）
1. **客户端退避**: 指数退避 (1.5s → 45s) + 40% 随机抖动，彻底消除惊群效应
2. **客户端熔断**: 12 次连续失败触发 5 分钟冷却，防止无效请求轰炸
3. **服务端限流**: 令牌桶 (80/s) + 滑动窗口 (800/10s) 双保险，快速拒绝超量请求
4. **服务端降级**: 三级负载感知，高负载下延迟握手或快速拒绝，保护核心服务
5. **前后端协同**: 限流时服务端返回 `retryAfter`，客户端自动调整重连节奏
